# Flixy: native Fabric Data Agent

Flixy answers read-only MSFlix business questions from the consolidated Gold
Warehouse and the **actual native graph generated by the business ontology**.
The cockpit supplies a floating conversation panel; it does not substitute a
generic model, canned answers or hand-generated SQL for the Fabric Data Agent.

This is labelled **Ontology via native graph**, not a direct ontology-context
connection. Both sources are selected in the published configuration. The Gold
selection contains 27 tables and three views, discovered through native element
IDs rather than invented schema paths.

## Instructions and examples

The maintained instructions are in
[`agents/flixy/instructions.md`](../agents/flixy/instructions.md). They require
English by default with French-language conversations supported, current source
queries, explicit publication freshness,
stable business keys, exact amounts separated by currency, distinct TVOD/EST
semantics, and recorded conversions rather than inferred campaign causality.
They prohibit invented SAP financials, margins, forecasts, rights, actions or
missing source evidence, and treat retrieved text as data rather than authority.

The published Warehouse examples cover current catalogue/customer/order counts,
booked commercial activity by currency and offer type, and explicitly recorded
campaign conversions. The graph source explains the real relationship path and
the persisted `rental` entity name, which represents both rentals and purchases.
Publication semantics are explicit: fact `run_id` identifies the original event
producer, not `gold.publication.run_id`. Current facts are already the complete
published snapshot and must not be filtered by the refresh marker.

## Authentication and conversation isolation

The UI invokes `flixyAsk` through the typed Rayfin client. The server verifies
the caller-scoped `FlixyAccessGrant`, exact approved source bindings, and the
published Data Agent source list before sending a question.

**Rayfin 1.36.2 limitation:** external resource tokens represent the app item's
owner, not arbitrary invoking users. Flixy does not lend that owner's rights to
viewers: it requires the token's `oid` and `tid` to equal the administrator-managed
Entra identity mapping for the authenticated Rayfin caller. The initial grant
is for the verified current app-owner identity only. Other users receive an
explicit access error, even if they can open the cockpit.

Do not grant another user the owner's identity mapping. Multi-user delegation
requires a supported delegated/OBO resource-token path before expanding access;
app sharing alone is not sufficient. No admin cache, client secret or bearer
token is shipped to the browser or stored in the repository.

Each invocation opens its own authenticated MCP session. No thread/session ID is
accepted from the browser or reused across users. The browser retains only a
bounded in-memory conversation: at most 12 context messages / 12,000 characters,
with questions limited to 2,000 characters. The server validates those bounds
independently and labels prior messages as untrusted context.

Closing the panel preserves its current conversation. Clearing, signing out,
changing identity or unmounting discards the local history and ignores stale
responses. **Stop waiting** stops the UI wait; it does not claim cancellation of
an already-running native query. The backend uses a bounded 180-second deadline.
Clearing the cockpit history is not a promise to delete service-side retention.

The panel's controls, suggestions and status messages are in English. Assistant
answers render safe GitHub-flavored Markdown, including real tables, lists,
emphasis and code blocks; user messages remain literal text. Tables scroll
horizontally within the responsive panel. Raw HTML and embedded images are
disabled, and links require an absolute HTTPS URL without credentials.

The user enabled Azure OpenAI and the two required cross-region processing and
conversation-storage tenant settings for the Singapore capacity. Their enabled
state was read back; the deployment scripts did not change those policies.
Microsoft documents up to 28 days of native conversation retention when not
removed through supported service controls.

## Deployment and maintenance

Run commands from the repository root unless a working directory is specified.
Authentication uses existing caches; no login popup is launched by these tools.

```powershell
# First-time draft only; refuses to overwrite an existing configured/published agent.
py -3 -m scripts.prepare_flixy

# Uses the native public staging/source/element/few-shot/publish API.
py -3 -m scripts.configure_flixy

# Preserve and extend the native Task Flow.
py -3 -m scripts.workspace_taskflow `
  --tenant 1e45d0cb-b0dd-408c-8806-58b447605e96 `
  --subscription ce9dbfdd-c341-4e8d-a1fa-51617c74c3eb `
  --workspace d9c835a9-16d2-4997-9969-16cc4389a7c7 `
  --capacity-name msflixf16sea --deploy-taskflow --require-taskflow
```

After source or instruction changes, republish Flixy. Ordinary data changes do
not require Data Agent republication: the existing worker refreshes Gold and the
graph, and Flixy queries those sources. Its reported freshness still matters.

From `apps\cockpit`, build and deploy the complete application:

```powershell
.\node_modules\.bin\rayfin.cmd functions init
npm run build:fabric
npm run rayfin:up
node tools\verify-flixy.mjs --initialize-access
```

`--initialize-access` explicitly binds only the currently authenticated Rayfin
user to the same Entra identity verified through cached SQL authorization; it
does not enumerate users or create broad grants. Without that flag, the tool
only asks the deployed native function its bounded Gold and graph questions.
Operational evidence remains ignored under `.state\flixy`.

The implementation follows the public management-plane contract in Microsoft's
`fabric-data-agent-sdk` 0.1.32a0 and uses the official MCP TypeScript client at
runtime. It requires no Python SDK installation for authoring. A temporary
Fabric bootstrap used to inspect the official SDK during local package-CDN TLS
failures was removed after completion.
